Tracks

State is earned from finished work and how it went — never from time spent. A bad recent run overrides a good lifetime average, because the question is what you can do now.

How it works

Three rules

The reward is the evidence. There are no points and no badges. Finishing a task puts an artifact on the desk. The grid filling up is the progress display. The streak counter exists, but its label says “days in a row showing up”, because that is all it measures.

Track state is earned from outcomes, never from time. Each track moves Not started → Building → Solid → Interview-ready on finished tasks and how they went. Two or more shaky results in the last four flags the track for review and overrides everything above it.

Reflection is four taps. One outcome, one optional friction chip, no text field. Those two signals drive the review flag and the recommender; a paragraph would not drive them any better and would not get written.

What the recommender does

Every task that fits your budget is scored, highest wins, and Different task takes the runner-up:

+40   track has the fewest finished tasks
+0–20 track untouched longest (3 points per day, capped)
−18   per previous completion of this exact task
+16   track currently flagged Needs review
+0–10 task length close to the budget

The weights are a first guess and visibly arbitrary. They live in one function (Engine.rank) precisely so they can be rewritten once there is real usage to tune against.

Your data

Everything is stored in this browser's localStorage under one key. Nothing is uploaded and there is no backend. The page is public; your log is not, because it never leaves this machine. That has a consequence: clearing site data erases it, and it does not travel to another browser. Export before you clear anything. Import merges by entry id, so restoring an old backup never destroys newer work.
